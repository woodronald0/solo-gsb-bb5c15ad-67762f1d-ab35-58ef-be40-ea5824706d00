# 口述史事件时间线核对

供口述史整理者核对多个事件“先后描述”是否自洽的小工具。整理者把访谈中得到的两事件时间差区间逐行粘贴，后端把全部区间联立为**差分约束系统**：

- 若约束互相矛盾，返回一条由**原始行号与对应上下界**构成的**闭合矛盾链**（负环），说明是哪几句话“打了架”；
- **冲突单行修订建议**：文本语法有效但联立矛盾时，逐行暂时移除该行的上、下界约束——其余行仍矛盾的行排除；其余可解时求这两个事件时间差的**最紧可行区间**，只放宽该行**一个端点**至首次相交的整数分钟，给出**最小改动量、替换后的整行**与迫使该端点移动的**原始行号、界值推导链**；建议按改动分钟数、原始行号排序，无单行修复时明确提示；
- 若无矛盾，返回一条以**最早事件为第 0 分钟**、满足全部区间的可行时间线，并逐条核对每个区间；
- **绝对时间锚定**：在区间文本旁粘贴多行 `事件名,YYYY-MM-DD HH:MM` 锚点（同一无时区本地时间），后端把每个锚点作为**事件相对统一零点的等式**与区间一起联立——同名锚点重复也参与判定；锚点与区间或彼此冲突时返回含**区间行号、锚点行号与所用界值**的闭合矛盾链；可解时只为**与锚点连通**的事件显示绝对日期时刻（精确点或范围），其余标为**“未定位”**，不把任何任意平移量当作真实日期；
- **约束冗余核对**：任选一条原始行，删去该行对应的上、下界约束后，求其余约束对这两个事件时间差的**最紧下界与上界**——推不出的端点标为**无界**，有界端点给出**推导路径、原始行号与所用界值**；仅当推导区间完全落在所选行区间内时判为**“可删”**，否则标为**“必要”**；
- **两版比较**：分别粘贴**基准文本**与**修订文本**，后端对两版**各自独立校验、独立联立**后按事件名对齐，返回共同事件的基准/修订时刻与**变化分钟数**、**导致变化的修订行号**（复用冗余核对同款最短路推导，给出每环修订行号、所用界及该行相对基准是“已修改/新增/区间未改”的证据链），并列出修订版的**新增事件**与**删除事件**；任一版无效或互相矛盾时，分别返回该版错误或闭合矛盾链，**不生成任何差异结论**；
- **互斥说法下的先后查询**：区间文本作**共同约束**，另输入最多 6 行**候选组**（每行 `区间A | 区间B`，两条说法只能选一条，两侧沿用区间格式），后端**枚举全部组合**与共同约束联立、**排除冲突组合**；对每个可行组合求 `t(乙) − t(甲)` 的**最紧上下界**，再跨组合取**最小下界、最大上界**（任一组合对应端无界则合并端无界）：合并下界 ≥ 1 分钟判**“甲始终先于乙”**，合并上界 ≤ −1 分钟判**“甲始终后于乙”**，否则判**“不确定”**；无可行组合时不作先后判断；
- **最少撤回**：当若干句叙述无法同时成立时，对最多 **10 条非空有效约束**按**撤回行数递增**搜索，返回所有使剩余约束可行的**最少撤回原始行号组合**；每个方案展示剩余约束的**一条可行时间线**（撤回全部行时显示空时间线）；**空约束集视为可行**，原文已可行时返回**零撤回方案**；语法错误或超限给出明确提示。

技术栈：Python 3.11 + FastAPI + 原生 JavaScript（无前端构建、无 npm）。

## 输入格式

每行一条：

```
事件甲,事件乙,最少分钟,最多分钟
```

含义：`最少分钟 ≤ 事件乙时刻 − 事件甲时刻 ≤ 最多分钟`（即“乙比甲晚”的时间差区间，分钟为整数；允许负数表示乙实际更早）。

- 支持半角 `,` 与中文逗号 `，`；
- 空行会被跳过，但**行号按原始文本计算**，矛盾链与错误提示引用的都是原始行号；
- 每行校验：事件名非空、上下界为整数、下界不大于上界。

示例（无冲突）：

```
起床,洗漱,10,30
洗漱,早饭,15,45
早饭,出门,20,60
出门,开会,40,90
起床,开会,80,240
```

页面上可一键填充“可行示例”与“矛盾示例”。

## 绝对时间锚定

整理者在区间文本旁的“绝对时间锚点”框中粘贴多行锚点，每行一条：

```
事件名,YYYY-MM-DD HH:MM
```

含义：该事件发生在指定的绝对时刻。日期按**同一无时区的本地时间**处理，精确到分钟；后端把每个锚点换算为相对**统一零点**（公历 0001-01-01 00:00）的分钟数，作为**事件相对零点的等式**与区间行一起联立（复用同一套差分约束与 Bellman-Ford）：

- **同名锚点重复也参与判定**：同一事件的两条锚点等式互相校验，时刻不同即构成冲突；
- **冲突**：锚点与区间、或锚点彼此矛盾时，返回含**区间行号、锚点行号与所用界值**的闭合矛盾链（链上零点节点显示为“统一零点”）；
- **可解**：只为**与锚点连通**的事件显示绝对日期时刻——其余约束推出的最紧下界/上界相等时为**精确**时刻，否则为**范围**；与任何锚点都不连通的事件标为**“未定位”**，**不把任何任意平移量当作真实日期**；
- 区间文本可留空（纯锚点模式），锚点文本为空时报错提示。

页面操作：在“事件区间”框粘贴区间（或点“填入可行示例”），在“绝对时间锚点”框粘贴锚点（或点“填入锚点示例”，区间框为空时会自动填入可行示例配合演示），点击**“锚定求解”**；下方显示统计横幅、各事件的绝对时刻表（精确/范围/未定位）与本次使用的锚点列表。编辑任一文本框后旧的锚定结果自动清空。

示例（配合“填入可行示例”的 6 行区间）：

```
起床,2024-03-05 06:30
开会,2024-03-05 09:00
```

结果：起床、开会精确定位（06:30、09:00，相差 150 分钟，落在第 5 行 [80,240] 内）；洗漱 06:40~07:00、早饭 06:55~07:45、出门 07:30~08:20（范围）。

## 约束冗余核对

整理者在文本中**任选一条原始行**，后端删去该行对应的上、下界两条约束后，在其余约束上求这两个事件时间差的**最紧下界与上界**：

- 推不出的端点标为**无界**（`null`）；
- 有界端点给出**推导路径**：路径上每一环都标注**原始行号、所用界（上界/下界）与界值**；
- 判定规则：推导区间**完全落在**所选行区间内（推导下界 ≥ 原下界 且 推导上界 ≤ 原上界）⇒ **可删**；任一端点无界或超出 ⇒ **必要**；
- 输入无效或原约束互相冲突时，接口直接返回现有 `/api/solve` 的求解结果（错误列表或矛盾链）。

页面操作：粘贴文本后，在“约束冗余核对”区的下拉框中选择一条原始行（选项即原始行号与行内容），点击**“核对所选行”**，下方即显示结论横幅（可删/必要）、区间对比表与两个端点的推导路径链图及明细表。

示例：点“填入可行示例”后，第 5 行 `起床,开会,80,240` 与第 6 行 `起床,早饭,25,90` 均会被判为**可删**（第 5 行由第 1–4 行推出 [85, 225] ⊆ [80, 240]）；第 1–4 行则为**必要**。

## 冲突单行修订建议

文本**语法有效但联立矛盾**时，后端遍历每条原始约束行，**逐行暂时移除该行的上、下界约束**后对其余行重新联立：

- **其余行仍矛盾** ⇒ 该行排除（只改它一个端点救不回其余行自身的矛盾）；
- **其余行可解** ⇒ 复用冗余核对同款最短路推导，求出其余约束对这两个事件时间差的**最紧可行区间** `[推导下界, 推导上界]`，然后只放宽该行**一个端点**至**首次相交的整数分钟**：
  - 上界冲突（推导上界 < 原下界）：只把**下界**放宽到推导上界，改动 `原下界 − 推导上界` 分钟；
  - 下界冲突（推导下界 > 原上界）：只把**上界**放宽到推导下界，改动 `推导下界 − 原上界` 分钟；
  - 区间含整数端点，移到边界即首次相交，改动量最小；另一个端点保持不动。

每条建议给出：**最小改动分钟数、替换后的整行**（事件名与原行号不变，只换一个端点），以及**迫使该端点移动的原始行号与界值推导链**（推出那个紧界的最短路路径，每环标注原始行号、所用界与界值）。建议按**改动分钟数、原始行号**升序排序；没有任何单行修复时明确提示“没有单行修复方案”。输入未通过校验时返回逐行错误；原文本可解时明确说明**无需修订**。

页面操作：粘贴矛盾文本（或点“填入矛盾示例”）后，点击“冲突单行修订建议”区的**“获取修订建议”**，下方逐条显示建议卡片（改动量、替换后的整行、推导链链图与明细表）；点击卡片上的**“填入此建议”**会把替换后的整行写回上方文本框对应原始行号并自动重新联立确认可解；**编辑文本后旧建议自动清空**。

接口用法（curl）：

```bash
curl -X POST http://localhost:8080/api/repair \
  -H 'Content-Type: application/json' \
  -d '{"text": "早饭,开会,30,60\n开会,晚饭,45,90\n晚饭,早饭,20,50"}'
```

返回（节选，矛盾示例的三条建议改动量相同，按行号排序）：

```json
{
  "status": "conflict",
  "conflict": { "steps": [ /* 与 /api/solve 相同的闭合矛盾链 */ ], "weight_sum": -95, "closes_to": "晚饭" },
  "suggestion_count": 3,
  "checked_lines": 3,
  "suggestions": [
    {
      "line": 1, "a": "早饭", "b": "开会", "low": 30, "high": 60,
      "endpoint": "low", "endpoint_label": "下界（最少分钟）",
      "old_value": 30, "new_value": -65, "change_minutes": 95,
      "new_line": "早饭,开会,-65,60",
      "derived_low": -140, "derived_high": -65,
      "forcing_lines": [3, 2],
      "forcing_path": [ /* 第3行下界 20、第2行下界 45 的推导环，含行号/所用界/界值/含义 */ ]
    }
  ]
}
```

## 两版比较

整理者把口述稿的**基准版**与**修订版**区间文本分别粘贴到两个文本框，点击**“比较两版”**。后端对两版**完全独立**地执行现有解析与联立求解（复用同一套 `parse_text` 与 Bellman-Ford 逻辑），再按**事件名对齐**：

- **共同事件**：给出基准时刻、修订时刻与**变化分钟数**（正数为推迟、负数为提前、0 为未变）；
- **导致变化的修订行**：对每个分钟发生变化的共同事件，复用冗余核对同款**最短路推导**（修订版中从第 0 分钟锚点事件到该事件的最紧上界 / 反向最短路取负的最紧下界，规范化可行解恰好顶在其中一个紧界上），把推出修订时刻的路径作为证据——路径上每环都标注**修订行原始行号、所用界（上界/下界）与界值**，并标注该行相对基准是**“已修改 / 新增 / 区间未改”**；
- **新增 / 删除事件**：仅修订版出现的事件标为**新增**（列出修订时刻），仅基准版出现的事件标为**删除**（列出基准时刻）；
- **第 0 分钟锚点**：两版优先取**共有的第 0 分钟事件**作锚点，使共同事件的变化分钟数不夹带整体平移；若两版零分钟事件没有交集（页面给出提示），与锚点分属互不连通事件组件的事件标为**“不可比”**，其分钟差只是各组件独立归零的假象，不计为变化；
- **失败不产生差异**：任一版校验无效（逐行错误）或存在闭合矛盾链（负环）时，接口返回 `status: "invalid"`，在 `base` / `revised` 字段中**分别**带回该版与 `/api/solve` 完全相同的错误列表或矛盾链，页面左右两栏分别展示，**不生成对齐表或差异结论**；
- 任一输入框内容变化时，页面立即**清空旧的比较结果**，避免展示与输入不一致的结论。

页面操作：在“两版比较”区两个文本框中分别粘贴（或点**“填入两版示例”**），点击**“比较两版”**；下方显示统计横幅、**事件对齐表**（类型 / 事件 / 基准时刻 / 修订时刻 / 变化分钟 / 导致变化的修订行号）以及每个变化事件的**变更行证据**卡片（推导路径链图 + 明细表）。

接口用法（curl）：

```bash
curl -X POST http://localhost:8080/api/compare \
  -H 'Content-Type: application/json' \
  -d '{
    "base": "起床,洗漱,10,30\n洗漱,早饭,15,45",
    "revised": "起床,洗漱,15,35\n洗漱,早饭,20,50"
  }'
```

返回（节选）：

## 互斥说法下的先后查询

同一事件的经过常有多种互相矛盾的说法。整理者把**所有说法都认可的约束**留在“事件区间”文本中作**共同约束**，把**只能二选一的说法**按行填入“互斥说法候选组”，再指定要查询先后关系的两个事件，后端枚举全部取舍组合后给出稳健结论。

**输入格式**：

- 共同约束：沿用“事件区间”文本（每行 `事件甲,事件乙,最少分钟,最多分钟`）；
- 候选组：每行 `区间A | 区间B`，两侧均沿用同一区间格式，表示该行的两条说法**只能选一条**；**最多 6 行**（每行二选一，组合数为 2 的幂，限制行数保证枚举耗时可控）；支持中文逗号 `，` 与中文竖线 `｜`；空行跳过但行号按原始文本计算；
- 查询事件：填写**事件甲**与**事件乙**，两者**必须出现在共同约束中**（且不能相同）。

**判定规则**：枚举全部 `2^N` 个“每组选一侧”的组合，分别与共同约束联立（同一套差分约束 Bellman-Ford），存在负环的组合判为**冲突组合**并排除；对每个**可行组合**复用冗余核对同款最短路推导求 `t(乙) − t(甲)` 的**最紧下界/上界**（推不出的端点为无界），再跨组合合并——**下界取各组合最小值、上界取各组合最大值，任一组合对应端无界则合并端无界**：

- 合并下界 **≥ 1 分钟** ⇒ **甲始终先于乙**（无论互斥说法如何取舍）；
- 合并上界 **≤ −1 分钟** ⇒ **甲始终后于乙**；
- 其余 ⇒ **不确定**；
- **无可行组合 ⇒ 不作先后判断**。

页面操作：在“事件区间”框粘贴共同约束（或点“填入可行示例”），在“互斥说法下的先后查询”区填写查询事件甲、乙与候选组（或点**“填入互斥示例”**，共同约束为空时自动填入可行示例配合演示），点击**“先后查询”**；下方显示结论横幅、**可行/冲突组合数与合并区间**、候选组对照表与逐组合明细（每组所选一侧、联立结果、可行组合的最紧区间）。编辑任一相关输入后旧结论自动清空。

接口用法（curl）：

```bash

    "text": "起床,洗漱,10,30\n洗漱,早饭,15,45\n早饭,出门,20,60\n出门,开会,40,90\n起床,开会,80,240\n起床,早饭,25,90",
```

## 最少撤回

几句叙述实在无法同时成立时，整理者往往想知道“**最少撤回哪几行**，剩下的就能自洽”。本模块直接使用页面上方“事件区间”文本（现有 `事件甲,事件乙,最少分钟,最多分钟` 格式），后端复用同一套区间解析与差分约束联立求解：

- **输入限制**：最多 **10 条非空行**（空行跳过、行号按原始文本计算）；搜索按撤回行数枚举全部行号组合，组合数随行数快速增长，限 10 条保证耗时可控，超限返回明确错误；
- **搜索规则**：先检查原文本身（撤回 0 行）；不可行时按撤回行数 `k = 1, 2, …` 递增枚举 `C(n, k)` 个原始行号组合，对每个组合把其余行重新联立（同一套 Bellman-Ford），**第一个存在可行剩余子集的 k 即最少撤回数**，返回该层**全部**可行组合；
- **空约束集视为可行**：空文本（或只有空行）直接返回零撤回方案与空时间线；撤回全部行时方案的时间线为空；
- **原文已可行**：返回零撤回方案，时间线即原文的规范化可行解；
- **每个方案**展示撤回的原始行号、保留行数，以及剩余约束的**一条可行时间线**（以最早事件为第 0 分钟）；原文矛盾时另附原始闭合矛盾链（页面上可展开查看）。

页面操作：在“事件区间”框粘贴文本（或点“最少撤回”区的**“填入撤回示例”**——前 3 行构成闭合负环、第 4 行与冲突无关，撤回前 3 行中任意 1 行即恢复可行），点击**“最少撤回搜索”**；下方显示结论横幅（最少撤回行数、方案数、检查的组合数）、每个方案的撤回行对照表与剩余约束可行时间线，以及可展开的原始矛盾链。编辑文本后旧结论自动清空。

接口用法（curl）：

```bash
curl -X POST http://localhost:8080/api/withdrawals \
  -H 'Content-Type: application/json' \
  -d '{"text": "早饭,开会,30,60\n开会,晚饭,45,90\n晚饭,早饭,20,50\n睡觉,起床,360,480"}'
```

返回（节选：最少撤回 1 行，共 3 个方案；方案 1 撤回第 1 行后，剩余 3 行可行，时间线含与冲突无关的“睡觉→起床”链）：

```json
{
  "status": "ok",
  "minimum": 1,
  "total_lines": 4,
  "checked_combinations": 5,
  "message": "原 4 条约束互相冲突，最少撤回 1 行即可使剩余约束可行；共找到 3 个最少撤回方案，每个方案附剩余约束的一条可行时间线。",
  "original_feasible": false,
  "conflict": { "steps": [ /* 与 /api/solve 相同的闭合矛盾链 */ ], "weight_sum": -95, "closes_to": "开会" },
  "plans": [
    { "index": 1, "withdraw_count": 1, "withdrawn_lines": [1], "remaining_count": 3,
      "timeline": [ { "event": "睡觉", "minute": 0 }, { "event": "开会", "minute": 295 },
                    { "event": "晚饭", "minute": 340 }, { "event": "早饭", "minute": 360 },
                    { "event": "起床", "minute": 360 } ] },
    { "index": 2, "withdraw_count": 1, "withdrawn_lines": [2], "remaining_count": 3, "timeline": [ /* … */ ] },
    { "index": 3, "withdraw_count": 1, "withdrawn_lines": [3], "remaining_count": 3, "timeline": [ /* … */ ] }
  ]
}
```

其他情形：原文已可行时 `minimum` 为 0、`plans` 为单个零撤回方案（`withdrawn_lines` 为空，时间线即原文可行解）；空文本时 `total_lines` 为 0、方案时间线为空；撤回全部行才可行时方案的 `timeline` 为空数组。语法错误返回 `status: "error"` 与逐行错误（含原始行号）；超过 10 条非空行返回超限错误。

## 原理简介

对每行 `甲,乙,lo,hi` 建立两条最短路约束：

- `t乙 − t甲 ≤ hi`：边 `甲 → 乙`，权 `hi`（上界）
- `t甲 − t乙 ≤ −lo`：边 `乙 → 甲`，权 `−lo`（下界）

再加一个指向所有事件、权为 0 的虚拟源（实现上等价于所有距离初始化为 0），运行 Bellman-Ford：

- 第 N 轮仍能松弛 ⇒ 存在负环，沿前驱指针还原负环，并映射回每条边的**原始行号与上/下界值**，即页面展示的闭合矛盾链（环上权值之和 < 0，意味着推出 `0 < 0` 式的矛盾）；
- 否则得到一组可行时刻，整体平移令最小值为 0，即为“最早事件在第 0 分钟”的时间线。

**冗余核对的推导**：删去所选行的两条边后，以单源 Bellman-Ford 求最短路——

- `甲 → 乙` 最短路 = 其余约束能推出的 `t乙 − t甲` **最紧上界**（不可达 ⇒ 上界无界）；
- `乙 → 甲` 最短路取负 = 其余约束能推出的 `t乙 − t甲` **最紧下界**（不可达 ⇒ 下界无界）；
- 最短路经前驱指针还原为推导路径，路径上每条边映射回**原始行号与所用界值**，作为页面展示的证据。

**两版比较的对齐与证据**：两版文本分别走同一套“解析 → Bellman-Ford → 平移归零”流程，得到各事件规范化时刻后按事件名对齐求差；分钟变化事件的证据直接复用上述界推导——从修订版第 0 分钟锚点事件出发的两条最短路给出最紧上/下界，取与规范化时刻相等的那个紧界路径，路径上的修订行号即**导致变化的修订行**；任一版错误或负环时短路返回该版结果，不构造对齐结论。

**冲突单行修订建议的推导**：对每条原始行，删去其两条边后对其余行运行 Bellman-Ford——仍有负环则跳过该行；可解时用与冗余核对相同的两条单源最短路求出这两个事件时间差的最紧可行区间 `[dl, dh]`。`dh < 原下界` 时只把下界放宽到 `dh`（证据为推出最紧上界的路径），`dl > 原上界` 时只把上界放宽到 `dl`（证据为推出最紧下界的路径）；区间含整数端点，移到边界即首次相交的整数分钟，改动量最小。

**绝对时间锚定的联立**：每个锚点 `事件名,YYYY-MM-DD HH:MM`（同一无时区本地时间）换算为相对统一零点（0001-01-01 00:00）的分钟数 `M`，引入零点节点 ZERO 与一对等式边——`ZERO → 事件` 权 `M`（不晚于锚定时刻）、`事件 → ZERO` 权 `−M`（不早于锚定时刻），与区间行的上、下界边一起跑同一套 Bellman-Ford；同名锚点重复即两条等式互查，时刻不同自然形成负环。负环还原时锚点边映射回**锚点行号与锚定时刻**，区间边映射回**区间行号与上/下界值**，构成闭合矛盾链。可解时不取任何平移后的可行解充当日期：对每个事件用冗余核对同款单源最短路求其相对零点的最紧下界/上界（`ZERO→事件` 最短路为上界，`事件→ZERO` 最短路取负为下界），两端都有界（与锚点连通）才显示绝对日期时刻——两界相等为精确点，否则为范围；不连通的事件标为“未定位”。

**互斥说法下的先后查询**：候选组每行解析为两条互斥说法（复用区间行同款四字段校验），枚举全部 `2^N`（N ≤ 6）个“每组选一侧”的组合；每个组合 = 共同约束 + 各组所选一侧，走同一套建边与 Bellman-Ford——存在负环的组合判为冲突并排除。对每个可行组合，复用冗余核对同款 `_derive_bound` 最短路求 `t(乙) − t(甲)` 的最紧上界（`甲→乙` 最短路）与最紧下界（`乙→甲` 最短路取负），不可达的端点为无界。跨组合合并：下界取最小、上界取最大，任一组合对应端无界则合并端无界；合并下界 ≥ 1 判“甲始终先于乙”，合并上界 ≤ −1 判“甲始终后于乙”，否则不确定，无可行组合不作判断。

**最少撤回**：对最多 10 条非空有效约束，先试撤回 0 行（原文本身）；不可行时按撤回行数 `k = 1, 2, …` 递增枚举 `C(n, k)` 个原始行号组合，每个组合删去对应行的上、下界边后对其余行走同一套 Bellman-Ford——第一个存在可行剩余子集的 `k` 即最少撤回数，返回该层全部可行组合；每个方案的剩余约束经同一套“平移到最早事件为第 0 分钟”的规范化得到一条可行时间线，撤回全部行时为空约束集（视为可行），时间线为空。

## API

- `GET /` — 页面
- `GET /api/health` — 健康检查
- `POST /api/solve` — 请求体 `{"text": "甲,乙,30,60\n..."}`，返回：
  - `status: "ok"`：`timeline`（事件与分钟）、`differences`（逐条核对）；
  - `status: "conflict"`：`conflict.steps`（矛盾链每一环的行号、方向、上/下界与含义）；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号）。
- `POST /api/redundancy` — 请求体 `{"text": "...", "line": 5}`（`line` 为原始行号），返回：
  - `status: "ok"`：`verdict`（`"removable"` 可删 / `"necessary"` 必要）、所选行 `a/b/low/high`、推导区间 `derived_low/derived_high`（无界端点为 `null`，另有 `lower_bounded/upper_bounded` 布尔标记）、有界端点的推导路径 `lower_path/upper_path`（每环含 `line` 原始行号、`kind`/`kind_label` 所用界、`bound` 界值、`relation` 含义）；
  - `status: "conflict"` / `status: "error"`：与 `/api/solve` 完全相同的现有求解结果（原约束冲突或输入无效时沿用）。
- `POST /api/compare` — 请求体 `{"base": "...", "revised": "..."}`，两版各自独立解析与联立：
  - `status: "ok"`：`base`/`revised` 各含 `event_count/line_count/anchor`（第 0 分钟锚点事件），`anchor_shifted`（两版锚点是否不同），计数 `common_count/changed_count/added_count/removed_count/incomparable_count`，以及 `alignment` 对齐列表（每项 `kind` 为 `common`/`added`/`removed`/`incomparable`，含 `event`、`base_minute`、`revised_minute`、`delta`；分钟变化的共同事件另带 `evidence`：`direction`（顶在上界还是下界）、`bound`（紧界值）、`lines`（导致变化的修订行号，去重保序）、`path`（推导路径每环的行号、所用界、界值、含义及 `change`：`added`/`changed`/`unchanged`））；
  - `status: "invalid"`：不生成差异结论；`base`/`revised` 分别为该版完整求解结果——`status: "error"` 带逐行 `errors`（含原始行号），或 `status: "conflict"` 带闭合矛盾链；另一版若可解则带与 `/api/solve` 相同的 `timeline/differences`。
- `POST /api/repair` — 请求体 `{"text": "..."}`，复用现有解析与求解给出冲突单行修订建议：
  - `status: "conflict"`：`conflict`（与 `/api/solve` 相同的闭合矛盾链）、`checked_lines`（尝试过的行数）、`suggestion_count` 与 `suggestions` 建议列表（按改动分钟数、原始行号升序；每条含 `line` 原始行号、`a/b/low/high` 原行区间、`endpoint`/`endpoint_label` 被放宽的端点、`old_value/new_value`、`change_minutes` 最小改动分钟数、`new_line` 替换后的整行、`derived_low/derived_high` 其余行推导的最紧可行区间、`forcing_lines` 迫使该端点移动的原始行号、`forcing_path` 界值推导链——每环含行号、所用界、界值与含义）；`suggestions` 为空即无单行修复方案；
  - `status: "ok"`：原文本无冲突，`message` 说明无需修订；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号）。
- `POST /api/anchor` — 请求体 `{"text": "区间文本", "anchors": "锚点文本"}`（锚点每行 `事件名,YYYY-MM-DD HH:MM`，同一无时区本地时间；区间文本可留空为纯锚点模式）：
  - `status: "ok"`：`anchors`（解析后的锚点：`line` 锚点行号、`event`、`time` 规范化时刻、`minute` 相对零点分钟数）、`events`（每个事件 `located` 是否与锚点连通；连通时 `minute_low/minute_high` 相对零点的最紧界、`abs_low/abs_high` 对应日期时刻文本、`exact` 是否精确点，未连通时均为 `null`）、计数 `event_count/located_count/anchor_count/line_count`；
  - `status: "conflict"`：`conflict.steps` 闭合矛盾链，每环含 `source`（`"interval"` 区间行 / `"anchor"` 锚点行）、`line` 对应文本的原始行号、`kind`/`kind_label`（上界/下界/锚点）、`bound` 界值（锚点环另有 `anchor_time` 日期时刻文本）、`relation` 含义；
  - `status: "error"`：`errors`（区间行错误与锚点行错误合并，锚点错误以“锚点第N行”前缀标注）。
- `POST /api/precedence` — 请求体 `{"text": "共同约束区间文本", "groups": "区间A | 区间B\n…（最多 6 行）", "a": "事件甲", "b": "事件乙"}`（甲、乙须出现在共同约束中）：
  - `status: "ok"`：`group_count`（候选组数）、`combination_count`（组合总数）、`feasible_count`/`conflict_count`（可行/冲突组合数）、`merged_low`/`merged_high`（跨组合合并区间，端点无界时为 `null`，另有 `lower_bounded/upper_bounded` 布尔标记）、`verdict`/`verdict_label`（`before` 甲始终先于乙 / `after` 甲始终后于乙 / `undetermined` 不确定 / `no_feasible` 无可行组合不作判断）、`groups`（解析后的候选组：行号与 A/B 两侧说法）、`combinations`（逐组合明细：`picks` 各组所选一侧、`feasible`、可行组合的 `low/high` 最紧界与有界标记）；
  - `status: "error"`：`errors`（共同约束行错误、候选组错误——以“候选组第N行A/B侧”前缀标注——与查询事件校验错误合并，含原始行号）。
- `POST /api/withdrawals` — 请求体 `{"text": "区间文本"}`（现有区间格式，最多 10 条非空行），按撤回行数递增搜索最少撤回组合：
  - `status: "ok"`：`minimum`（最少撤回行数）、`total_lines`（有效约束行数）、`checked_combinations`（检查过的撤回组合数）、`message`（结论文案）、`original_feasible`（原文是否已可行）、`plans`（全部最少撤回方案：每个含 `index` 方案序号、`withdraw_count` 撤回行数、`withdrawn_lines` 撤回的原始行号、`remaining_count` 保留行数、`timeline` 剩余约束的一条可行时间线——撤回全部行时为空数组）；原文矛盾时另带 `conflict`（与 `/api/solve` 相同的闭合矛盾链）；空文本视为可行的空约束集，返回零撤回方案与空时间线；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号；非空行超过 10 条时带超限提示）。
